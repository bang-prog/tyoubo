## 1. 目的と背景

個人経営の洋服店で使う、レジ兼帳簿 Web アプリ。

- クレジットカードやコード決済には Square を使っていて、売上データは Square に残る。
- 現金で払われた分はデータが残らないため、帳簿づくりに手間がかかっている。
- 現金会計をこのアプリで行い、その場で売上データとして残す。それを Excel にまとめて帳簿づくりを楽にする。
- Square で受けたキャッシュレスの会計も、支払い方法を選んでこのアプリに記録できる(v1.4)。現金とキャッシュレスの売上を1つの帳簿にまとめられる。

## 2. 範囲

### MVP に含めるもの
| # | 機能 | 概要 |
|---|---|---|
| F1 | 商品管理 | 商品・カテゴリーの登録と編集。在庫はサイズ・色ごとに持つ |
| F2 | 会計 | 商品を選ぶ → 合計 → 支払い方法を選ぶ → 現金ならお預かり入力(電卓)とお釣り表示 → 確定 |
| F3 | 会計履歴・返品 | 日付ごとに会計を一覧。会計の一部または全部を返品し、返金を記録する |
| F4 | レジ締め | 釣り銭準備金と、閉店時に金種ごとに数えた現金から過不足を出して記録する |
| F5 | 帳簿 | 日別・月別・カテゴリー別に集計し、Excel(.xlsx)で出力する |
| F6 | 暗証番号 | 設定で有効にすると、開いたときなどに暗証番号(PIN)を求める |
| F7 | バックアップと復元 | 全データをファイルに書き出す・ファイルから戻す |
| F8 | 古いデータの削除 | 保存期間(3か月)を過ぎた月の会計データを削除する |

### MVP に含めないもの(後で検討)
- 値引き(%で指定する予定)
- Square の売上の取り込み、このアプリから Square の決済を呼び出すこと(Point of Sale API)
- 紙のレシート
- 複数の端末でのデータ共有、複数スタッフでの利用
- バーコード読み取り

## 3. 前提

| 項目 | 内容 |
|---|---|
| 利用者 | オーナー1人 |
| 端末 | **iPhone 1台**(Q1、Q5 で決定)。Safari でホーム画面に追加して使う。スマホの縦向きで使いやすいことを最優先にする(§10.1)。開発中の確認のため、iPad や PC のブラウザでも崩れずに動くようにしておく。タップとマウスクリックの両方で操作できるようにする |
| データの置き場所 | その端末のブラウザの中だけ。クラウドには保存しない |
| 通信 | 最初にアプリを開くときと、アプリを更新するときだけ必要。読み込んだあとは、通信がなくても会計できる |
| 支払い方法 | 現金、クレジットカード、電子マネー、QR コードの4種類(1回の会計で1つ)。キャッシュレスの決済と返金は Square のアプリで行い、このアプリには記録だけをする。ブランド(Visa、PayPay など)は記録しない |
| 税率 | 一律10%(衣料品のため)。設定で変えられるようにしておく |
| 価格 | 税込で登録する |
| 起動の仕方 | ホーム画面に追加したアイコンから、アプリとして起動する(PWA)。ブラウザのタブで開いて使う形にはしない。Safari がしばらく開かれていないサイトのデータを消すのを防ぐため |
| 日付 | 営業日は、端末の時計で会計した日の日付とする(日本時間)。営業時間は日付をまたがない |
| 定休日 | 設定として持たない。会計がない日は、帳簿で「会計なし」として表示する |
| 費用 | 0円(独自ドメインを取る場合だけ有料) |

## 4. 技術スタック

| 役割 | 採用するもの | 選んだ理由 |
|---|---|---|
| 言語 | TypeScript | 金額計算や型の間違いを書いているうちに見つけられる |
| 画面 | React + Vite | 1画面で操作が完結するアプリに向く。ビルドが速い |
| 画面遷移 | React Router | 6つのタブ画面の切り替え |
| データの保存 | IndexedDB(ブラウザの中のデータベース)と Dexie.js | iPad の Safari と PC の Chrome / Edge のどちらでも使える。Dexie.js を使うと、検索やトランザクションを短く書ける |
| データを画面に表示する | Dexie.js の `useLiveQuery` | データが変わると画面が自動で更新される。別のライブラリ(TanStack Query など)は使わない |
| スタイル | CSS Modules と CSS 変数 | モックのデザイントークン(色)をそのまま使う。ダーク表示にも対応する |
| フォント | BIZ UDPゴシック(@fontsource/biz-udpgothic) | ユニバーサルデザインのフォントで、数字の 0 と 8、1 と 7 などを見分けやすく、金額の打ち間違いに気づきやすい。アプリの中に含めるので、外部に通信しない。文章も数字もこのフォントを使う |
| 画面をまたぐ状態 | React の Context(CartProvider) | 会計の途中で別のタブを開いても、カートが消えないようにする |
| Excel 出力 | ExcelJS | ブラウザの中で .xlsx を作れる。列幅や書式も指定できる |
| ホーム画面への追加とオフライン | vite-plugin-pwa | ホーム画面からアプリのように起動でき、一度読み込めば通信なしでも動く |
| 暗証番号 | Web Crypto API(ブラウザの標準機能) | ライブラリを足さずにハッシュ化できる |
| テスト | Vitest と fake-indexeddb(計算ロジックやデータ処理)、Playwright(画面操作、フェーズ7以降) | |
| コードの品質 | ESLint と Prettier | |
| CI | GitHub Actions | プルリクエストごとに型チェック、lint、テストを回す |
| ホスティング | Cloudflare Pages | 画面のファイルを配るためだけに使う。GitHub と連携して自動でデプロイする。無料プランで足りる(ビルドは月500回まで、静的なファイルの通信量は無制限)。有料プランに申し込まない限り請求は来ない |

|---|---|
| 開発 | プルリクエストごとのプレビュー URL |

## 5. 機能仕様

### F1 商品管理

**商品**
| 項目 | 必須 | 内容 |
|---|---|---|
| 商品名 | ○ | |
| カテゴリー | ○ | カテゴリー一覧から選ぶ |
| 販売価格(税込) | ○ | 1円単位の整数。入力欄の下に、税抜金額と消費税額を自動で表示する |
| 仕入価格 | ○ | 1円単位の整数 |
| サイズ | ○ | 1つ以上。例:S, M, L / W28, W30 / F(フリー) |
| 色 | ○ | 1つ以上 |
| 在庫数 | ○ | サイズ × 色の表で入力する |

- サイズ × 色の組み合わせ1つを「バリエーション」と呼ぶ。在庫はバリエーションごとに持つ。
- 商品一覧は、商品名で検索でき、カテゴリーで絞り込める。在庫が0以下の商品は目立つように表示する。
- 商品やバリエーションを削除しても、データは実際には消さない(論理削除)。過去の売上が参照しているため。削除したものは会計画面に出さない。
- サイズや色を減らしたときも、そのバリエーションは論理削除する。
- サイズと色の入れ方
  - 候補をタップして選ぶ(もう一度タップすると外す)。選んだものは上に並べ、× でも外せる。
  - 候補は「よく使うもの」と「ほかの商品で使ったもの」(多く使われている順)。
    - サイズ:XS、S、M、L、XL、XXL / F(フリー)/ 5号〜15号 / 0〜4
    - 色:白、アイボリー、ベージュ、グレー、黒、ネイビー、ブラウン、カーキ、グリーン、ブルー、サックス、レッド、ピンク、イエロー、オレンジ、パープル
  - 候補にないものは「＋ ほかのサイズ」「＋ ほかの色」で1つずつ追加する。カンマなどで区切る必要はない。
  - サイズは決まった順(アルファベット → 号数 → 数字 → フリー)に自動で並べる。並びの決まっていないサイズは追加した順で最後に置く。色は選んだ順。
  - 全角の英数字は半角に、余分な空白は1つにそろえる。全角・半角や大文字・小文字だけが違うもの(「Ｍ」「m」「M」)は同じものとして扱う。
  - 1つの名前は20文字まで。1つの商品にサイズは20個、色は30個まで。
  - 外したサイズや色に在庫が残っているときは、保存の前に注意を出す。

**カテゴリー**
- オーナーが自由に追加・名前の変更・並べ替えできる。
- 商品が登録されているカテゴリーは削除できない。

### F2 会計

**流れ**
1. カテゴリーで絞り込み、商品をタップする。
2. サイズと色を選ぶ。バリエーションが1つしかない商品は、選ぶ画面を出さずにそのまま追加する。
3. カートで数量を増やしたり減らしたりする。0にするとカートから消える。合計(税込)、税抜、うち消費税、点数を表示する。
4. カートで支払い方法を選ぶ(現金 / クレジットカード / 電子マネー / QR コード)。最初は現金を選んでおき、会計が終わるたびに現金に戻す。
5. **現金**:「お預かり金額を入力」を押すと電卓画面が開く。預かった金額を入力すると、お釣りを大きく表示する。足りない場合は赤で「不足」と金額を表示し、確定できない。「会計を確定」を押すと保存し、お釣りを大きく表示した完了画面を出す。
6. **キャッシュレス**:「(支払い方法)で会計」を押すと、合計と支払い方法を確認する画面が開く。Square のアプリで決済が終わったら「会計を確定」を押して保存する。お預かりは合計と同じ、お釣りは0円として記録する。
7. 完了画面の「次のお客様へ」で会計画面に戻る。

**電卓画面**
- 0〜9、00、1文字削除、クリアのキーを置く。
- 「ちょうど」(合計と同じ金額を入れる)、「＋1,000」「＋5,000」「＋10,000」(押すたびに足す)のボタンを置く。
- 金額は打ち間違いに気づけるよう大きく表示する。目安はお預かりとお釣りが 44〜72px、キーは高さ 64px 以上。
- 入力できるのは7桁(9,999,999円)まで。
- PC ではキーボードでも操作できる。数字キーで入力、Backspace で1文字消す、Enter で確定、Esc で戻る。

**在庫**
- 確定するとバリエーションの在庫を減らす。
- 在庫を超えて会計しようとしたときは警告を出すが、会計はできる。在庫数はマイナスになってもよく、商品管理で赤く表示して登録漏れに気づけるようにする。

**会計番号**
- 形式は `YYYYMMDD-NNN`。営業日ごとに001から振る。例:`20261023-007`

**バックアップの注意**
- 最後にバックアップしてから7日以上たったら、会計画面の上に「バックアップを保存してください」と表示する。ボタンを押すと、そのままバックアップを保存できる(F7)。

### F3 会計履歴・返品

- 日付を前後に切り替えられる。「今日」ボタンで今日に戻る。
- その日の会計件数、売上(うち現金)、返金額を表示する。
- 一覧と明細に支払い方法を表示する。キャッシュレスの会計では、お預かりとお釣りは表示しない。
- 会計の一覧は時刻の新しい順に並べる。1件選ぶと明細が出る。明細には商品、色・サイズ、数量、金額、合計、税抜、消費税、お預かり、お釣り、返金の記録を表示する。
- 削除済みの月(F8)を表示したときは「この月のデータは削除済みです」と表示する。

**返品**
- 明細の商品ごとにチェックを入れて返品する。数量が2以上の明細は、返品する数を選べる(返品できるのは、まだ返品していない数まで)。
- 画面の中で返金額を確認してから「返品を確定」を押す。ブラウザの確認ダイアログは使わない。
- 確定すると返金を記録し、在庫を戻す。元の会計は変更せず、明細に「返品済み」と表示する。
- キャッシュレスの会計の返金は、元の会計と同じ支払い方法で記録する。実際の返金は Square のアプリで行うよう、確定の前と後に画面で案内する。
- 返金は返品した日の営業日に記録する。過去の日の会計を今日返品した場合も、今日の返金になる。
- 返品できるのは、データが残っている会計だけ(保存期間は3か月。F8)。

### F4 レジ締め

- 1営業日につき1件記録する。保存し直すと上書きする。
- 入力するもの
  - 開店時の釣り銭準備金(前日の値を最初から入れておく)
  - 閉店時に数えた枚数:1万円札、5千円札、2千円札、千円札、500円玉、100円玉、50円玉、10円玉、5円玉、1円玉。＋−ボタンでも、数字の入力でも入れられる
  - メモ(過不足の理由など)
- 自動で計算するもの
  - レジにあるはずの現金 = 準備金 + その日の現金売上 − その日の現金の返金
  - キャッシュレスの売上と返金はレジの現金に関係しないので含めない(画面には参考として表示する)
  - 数えた現金 = 金種ごとに「額面 × 枚数」を足したもの
  - 過不足 = 数えた現金 − レジにあるはずの現金
- 過不足は、0なら緑で「過不足なし」、プラスなら黄で「過剰」、マイナスなら赤で「不足」と表示する。
- 保存した時点の売上と返金の値も記録しておく。後で会計が変わっても、締めた時点の数字が残るようにするため。
- **保存すると、続けて「バックアップを保存」ボタンを表示する。** 毎日の締めの作業にバックアップを組み込むため。

### F5 帳簿

- 日別表示(月を選ぶ)と月別表示(年を選ぶ)を切り替えられる。
- 集計の数字:会計件数、売上(税込)、税抜、消費税、返金、差引売上(売上 − 返金)
- 日別表示では、会計がない日も一覧に表示し、「会計なし」とする(定休日の設定は持たない)。
- カテゴリー別には、点数、売上(税込)、構成比を表示する。
- 支払い方法別に、件数、売上(税込)、返金を表示する。返品は差し引かずに数える(返金は別の期間に入ることがあるため)。
- 「この月(この年)の Excel をダウンロード」で、表示している期間の .xlsx を保存する(§7)。
- 日別表示では、会計か返品がある日の行に「保存」ボタンを置き、**その日1日分の .xlsx** を保存できるようにする。
- 月別表示では、会計か返品がある月の行に「保存」ボタンを置き、**その月1か月分の .xlsx**(日別表示の「この月の Excel」と同じ中身)を保存できるようにする。
- Excel を出力した月は記録しておき、F8 の削除画面で「出力済み」と表示する。1日分の出力は、その月のほかの日を含まないので、月を出力したことにはしない。
- 削除済みの月は、集計の代わりに「削除済み」と表示する。

### F6 暗証番号(PIN)

- 設定画面で、オンとオフを切り替える。最初はオフ。
- 4〜6桁の数字。設定するときは2回入力して確認する。
- オンのときは、タブやアプリを閉じたあと、もう一度開いたときだけ PIN の入力画面を出す。開いたままなら、時間がたっても求めない。PIN の入力画面は数字キーで入力する。
  - iPad でホーム画面から使う場合は、アプリを上にスワイプして終了し、もう一度開いたときに求める。別のアプリに切り替えて戻っただけなら求めない。
  - 同じタブで画面を再読み込みしたときは求めない。
- 5回続けて間違えたら、30秒間は入力できないようにする。
- PIN はそのまま保存しない。PBKDF2(SHA-256)でハッシュ化し、ソルトと一緒に保存する。
- PIN を設定したときに、12文字の「復旧コード」を1回だけ表示する。PIN を忘れたときは、このコードを入れて PIN を解除する。復旧コードもハッシュ化して保存する。
- **これは他の人に画面を触られないための簡易なロックで、データの暗号化ではない。** 設定画面にもそう書いておく。

### F7 バックアップと復元

**バックアップ(書き出し)**
- 全データ(商品、在庫、会計、返品、レジ締め、設定)を1つのファイルに書き出す。PIN と復旧コードのハッシュは含めない。
- ファイル名:`レジ帳簿_バックアップ_2026-10-24.json`
- ファイルの中身:アプリ名、データ形式のバージョン、書き出した日時、各テーブルのデータ
- 保存先は端末によって変わる。iPad なら「ファイル」アプリか iCloud Drive、PC ならダウンロードフォルダなど。保存先は画面に案内を出す。
- 書き出した日時を記録し、設定画面と F2 の注意に使う。
- バックアップを促すタイミング
  - レジ締めを保存したあと(F4)
  - 最後のバックアップから7日以上たったとき(F2)
  - 古いデータを削除する前(F8)

**復元(読み込み)**
- 設定画面で、バックアップファイルを選んで読み込む。
- 読み込む前に、ファイルの書き出し日時と件数を表示する。そのうえで「今のデータはすべて置き換わります」と画面の中で確認してから実行する。
- アプリ名とデータ形式のバージョンを確認し、合わないファイルは読み込まない。
- 置き換えは1つのトランザクションで行う。途中で失敗したら、元のデータのまま残す。
- 端末を変えるときも、このバックアップと復元でデータを移す。

### F8 古いデータの削除

- 帳簿の画面に「古いデータの削除」を置く。**自動では削除しない。** オーナーが操作したときだけ削除する。
- 保存期間は3か月。削除できるのは、今月と直近3か月を除いた、それより前の月。
  - 例:10月24日なら、7・8・9・10月は残し、6月以前の月を削除できる。
- 削除の画面には、月ごとに次のことを表示する。
  - 会計の件数
  - Excel を出力したか(出力済み / 未出力)
  - 最後のバックアップより前の月か
- Excel を出力していない月は、チェックを入れても削除できないようにし、先に出力するよう案内する。
- 削除の前にバックアップを促す。画面の中で月と件数を確認してから実行する。
- 削除するのは、その月の会計、会計の明細、返品、レジ締め。商品、在庫、カテゴリー、設定は残す。
- 削除した月は記録しておき、会計履歴と帳簿で「削除済み」と表示する。
- 画面に、次の注意を書いておく。
  > 書き出した Excel がお店の正式な帳簿になります。7年間保存してください。電子データのまま保存する場合のルールは、税理士か税務署に確認してください。

## 6. 金額と税の計算ルール

- 金額はすべて円単位の整数で扱う。小数は使わない。
- 消費税は、1回の会計(1枚の取引)ごとに税込合計からまとめて計算し、1円未満は切り捨てる。インボイス制度の端数処理のルールに合わせる。
  - 消費税額 = floor(税込合計 × 10 ÷ 110)
  - 税抜金額 = 税込合計 − 消費税額
  - 例:税込合計 11,270円 → 消費税 1,024円、税抜 10,246円
- 返金も、1回の返品ごとに同じ式で消費税額を出す。
- 明細ごとの消費税額は持たない。カテゴリー別の集計は税込金額で出す。
- お釣り = お預かり − 税込合計。マイナスになる会計は保存できない。
- 計算は `src/lib/money.ts` にまとめ、単体テストを書く。

## 7. Excel 出力

- ファイル名:1か月分は `帳簿_2026-10.xlsx`、1年分は `帳簿_2026.xlsx`、1日分は `帳簿_2026-10-24.xlsx`。1日分でもシートの構成は同じで、中身がその日の分だけになる
- 金額の列は数値として出力し、表示形式は `#,##0` にする。Excel でそのまま足し算などに使えるようにするため。

| シート | 1行の内容 | 列 |
|---|---|---|
| 集計 | 1日(または1か月) | 日付、件数、売上(税込)、税抜、消費税、返金(税込)、返金の消費税、差引売上、備考(会計も返品もない日は「会計なし」)。最後の行に合計 |
| 会計一覧 | 1会計 | 会計番号、日付、時刻、支払い方法、点数、合計(税込)、税抜、消費税、お預かり、お釣り(お預かりとお釣りは現金のときだけ) |
| 売上明細 | 1明細 | 会計番号、日付、時刻、商品名、カテゴリー、色、サイズ、数量、単価(税込)、金額(税込)、返品数 |
| 返品 | 1返品 | 返品日、時刻、元の会計番号、返品した商品(例:「ソックス(白/フリー)×1」を読点でつなぐ)、点数、返金方法、返金額(税込)、税抜、消費税、メモ。消費税は返品ごとに計算しているので、1回の返品を1行にする |
| カテゴリー別 | 1カテゴリー | カテゴリー、点数、売上(税込)、構成比(0.0% の形)。最後の行に合計 |
| 支払い方法別 | 1支払い方法 | 支払い方法、件数、売上(税込)、返金(税込)、差引売上。最後の行に合計 |
| レジ締め | 1営業日 | 日付、準備金、現金売上、返金、レジにあるはずの現金、数えた現金、過不足、メモ、保存した日時 |

## 8. データモデル

IndexedDB に保存し、Dexie.js で扱う。ID は `crypto.randomUUID()` で作る。日時は ISO 8601 形式の文字列(日本時間)、営業日は `YYYY-MM-DD` の文字列で持つ。

```
categories             id, name, sortOrder, createdAt

products               id, name, categoryId, priceIncl, cost, isActive, createdAt, updatedAt

variants               id, productId, size, color, stock(マイナス可),
                       sizeOrder, colorOrder, isActive
                       索引:[productId+size+color]

sales                  … 1会計
                       id, saleNo(YYYYMMDD-NNN), businessDate, soldAt,
                       totalIncl, taxAmount, totalExcl, received, change,
                       paymentMethod(cash / card / emoney / qr。v1.3 までのデータにはなく、現金として扱う)
                       索引:saleNo(一意)、businessDate

saleItems              … 会計の明細
                       id, saleId, variantId,
                       productName, categoryName, size, color,   ← 会計時点の値を保存しておく
                       unitPriceIncl, qty, lineTotal, returnedQty
                       索引:saleId

refunds                … 1回の返品
                       id, saleId, businessDate, refundedAt,
                       amountIncl, taxAmount, amountExcl, memo,
                       paymentMethod(元の会計と同じ。ないときは現金)
                       索引:saleId、businessDate

refundItems            id, refundId, saleItemId, qty, amountIncl
                       索引:refundId

closings               … レジ締め(主キー:businessDate)
                       businessDate, openingFloat,
                       cashSales, refundsTotal, expected,   ← 締めた時点の値
                       counts(例:{"10000":3,"5000":1,…}), countedTotal, difference,
                       memo, closedAt

settings               … キーと値(主キー:key)
                       taxRate, lastFloat, lastBackupAt,
                       exportedMonths(Excel を出力した月の一覧), purgedMonths(削除した月の一覧),
                       pinEnabled, pinHash, pinSalt, recoveryHash
```

- 金額はすべて整数(円)で持つ。
- 商品名、カテゴリー名、価格は会計の時点で `saleItems` に書き写す。後で商品を編集しても、過去の帳簿が変わらないようにするため。
- 集計は、`sales` を `businessDate` で、`refunds` を自分の `businessDate` で集計する。
- テーブルの形を変えるときは、Dexie.js のバージョン番号を上げ、古い形のデータを新しい形に変換する処理を書く。バックアップファイルにもデータ形式のバージョンを入れる。

## 9. 処理の一貫性と安全性

- 会計の確定、返品の確定、復元、古いデータの削除は、それぞれ1つの IndexedDB トランザクションで処理する。途中で失敗したら全部取り消す。
  - 会計の確定:合計と税を計算し、会計番号を振り、`sales` と `saleItems` を作り、在庫を減らす。お預かりが合計より少なければエラーにする。
  - 返品の確定:返品できる数を超えていないか確かめ、`refunds` と `refundItems` を作り、`returnedQty` と在庫を更新する。
- 合計金額は、画面に表示している値ではなく、トランザクションの中でバリエーションの現在の価格から計算し直す。
- 確定ボタンは押したらすぐ無効にし、二重に保存されないようにする。
- アプリを開いたときに永続ストレージ(`navigator.storage.persist()`)をリクエストする。ブラウザに空き容量が少なくなっても、データを消されにくくするため。
- Safari は、しばらく開かれていないサイトのデータを消すことがある。そのため、ホーム画面に追加して使うことを前提にし、最初に開いたときに追加の手順を案内する。
  - 案内は iPhone・iPad の Safari のタブで開いたときだけ出す。「あとで」はそのタブを閉じるまで、「今後は表示しない」はその端末では出さない。設定画面にも手順を載せる。
  - Safari のタブとホーム画面のアプリは保存場所が別なので、データは移らない。移すときはバックアップと復元を使う。案内にもそう書く。
- PWA(vite-plugin-pwa)
  - 画面のファイルと Excel の部品は、最初に開いたときに端末に保存し、電波がなくても開ける。
  - フォントは文字の範囲ごとに分かれていて大きい(約 6MB)ので、表示に使った分だけ保存する。保存していない文字をオフラインで表示するときは、端末の標準のフォントになる。
  - 新しい版を公開しても、自動では入れ替えない。会計の途中で画面が変わらないように、画面の上に「新しい版があります」と出し、「更新する」を押したときに読み込み直す。カートに商品があるときは、カートが消えることを書き添える。開いたままでも1時間ごとに新しい版を確かめる。
- データは端末の外に送らない。外部のサービスには通信しない(アプリ本体の読み込みと更新を除く)。

## 10. 非機能要件

| 項目 | 内容 |
|---|---|
| 操作性 | ボタンは高さ 44px 以上、主な操作のボタンは 64px 以上。マウスのホバーがないと使えない操作は作らない。ダブルタップでの拡大を防ぐ(`touch-action: manipulation`) |
| 画面サイズ | **スマホの縦向き(幅 360〜430px)を基準にする**(§10.1)。iPad や PC でも崩れないこと |
| 表示 | ライト表示とダーク表示の両方に対応する |
| 速さ | 会計を確定してから完了画面が出るまで、0.5秒以内を目安にする |
| オフライン | 一度読み込めば、通信がなくても全機能を使える |
| データ量 | 1日20会計なら、3か月分で約1,800件。IndexedDB の容量には十分余裕がある |
| エラー | 保存に失敗したときは、何が起きたかと、どうすればいいかを画面に表示する。カートの中身は消さない |
| ブラウザ | **iPhone の Safari**(iOS の最新版と1つ前)。開発中の確認用に PC の Chrome と Edge(最新版) |

### 10.1 スマホ対応で直すこと(フェーズ7で実装する)

今の画面は iPad や PC の横長の画面を前提に作っている。スマホの縦向きで使いやすくするため、次を直す。

| 場所 | 今の作り | スマホでの方針 |
|---|---|---|
| 全体のタブ | 画面上に6つのタブを横に並べている(狭いと横スクロール) | 画面下に固定したタブバーにする。親指で届く位置に、よく使う「会計」を置く。6つが収まらない場合は「その他」にまとめる |
| 会計 | 左に商品、右にカート | 商品の一覧を全面に出し、画面下に「合計 ¥◯◯ / ◯点」と「会計へ」のバーを固定する。タップするとカートを下から開く |
| 電卓 | 左に金額、右にキー | 縦1列で、お会計・お預かり・お釣りを上、キーを下にして、スクロールせずに1画面に収める |
| サイズ・色を選ぶ画面 | 色 × サイズの表 | 画面の幅に収まるように、ボタンを折り返して並べる |
| 商品管理 | 左に一覧、右に入力欄 | 一覧から商品を選ぶと、入力欄を全面に開く。在庫数の表は横スクロールできるようにする |
| 会計履歴 | 左に一覧、右に明細 | 一覧から選ぶと明細を全面に開き、「戻る」で一覧に戻る |
| 帳簿・レジ締め | 表を横に並べている | 表は横スクロールにするか、1行をカードにして縦に並べる |
| 入力欄 | 文字の大きさは 14〜15px | **16px 以上にする**。iPhone の Safari は、16px 未満の入力欄をタップすると画面が勝手に拡大されるため |
| 画面の端 | 上下左右のセーフエリアは一部だけ対応 | ノッチ(画面上の切り欠き)やホームバーに、ボタンや文字が重ならないようにする |

確かめ方:使う端末の実機で、会計 → 返品 → レジ締め → 帳簿の出力を一通り行う。
