# レジ帳簿 仕様書(MVP)

- 版:1.0(2026-10-23)
- 画面モック:[mockup/index.html](../mockup/index.html)

---

## 1. 目的と背景

個人経営の洋服店で使う、現金会計向けのレジ兼帳簿 Web アプリ。

- クレジットカードやコード決済には Square を使っていて、売上データは Square に残る。
- 現金で払われた分はデータが残らないため、帳簿づくりに手間がかかっている。
- 現金会計をこのアプリで行い、その場で売上データとして残す。それを Excel にまとめて帳簿づくりを楽にする。

## 2. 範囲

### MVP に含めるもの
| # | 機能 | 概要 |
|---|---|---|
| F1 | 商品管理 | 商品・カテゴリーの登録と編集。在庫はサイズ・色ごとに持つ |
| F2 | 会計 | 商品を選ぶ → 合計 → お預かり入力(電卓) → お釣り表示 → 確定 |
| F3 | 会計履歴・返品 | 日付ごとに会計を一覧。会計の一部または全部を返品し、返金を記録する |
| F4 | レジ締め | 釣り銭準備金と、閉店時に金種ごとに数えた現金から過不足を出して記録する |
| F5 | 帳簿 | 日別・月別・カテゴリー別に集計し、Excel(.xlsx)で出力する |
| F6 | ログイン | オーナー1人が使うためのログイン |

### MVP に含めないもの(後で検討)
- 値引き(%で指定する予定)
- Square の売上の取り込み
- 紙のレシート
- 複数スタッフでの利用、権限管理
- バーコード読み取り
- オフラインでの会計

## 3. 前提

| 項目 | 内容 |

### 環境
| 環境 | Supabase | Cloudflare Pages |
|---|---|---|
| 開発 | 開発用プロジェクト | プルリクエストごとのプレビュー |
| 本番 | 本番用プロジェクト | `main` ブランチ |

Supabase の無料プランでは2プロジェクトまで作れるので、開発用と本番用を分ける。

### 無料プランの注意点
- Supabase の無料プランは、1週間使われないとデータベースが一時停止する。毎日使えば問題ない。長期休業の前は気をつける。
- Supabase の無料プランには自動バックアップがない。代わりに GitHub Actions で週1回データベースのダンプを取る(§10)。
- Vercel の無料プランは商用利用ができないため使わない。

## 5. 機能仕様

### F1 商品管理

**商品**
| 項目 | 必須 | 内容 |
|---|---|---|
| 商品名 | ○ | |
| カテゴリー | ○ | カテゴリー一覧から選ぶ |
| 販売価格(税込) | ○ | 1円単位の整数。入力欄の下に、税抜金額と消費税額を自動で表示する |
| 仕入価格 | ○ | 1円単位の整数 |
| サイズ | ○ | 1つ以上。例:S, M, L / W28, W30 / F(フリー) |
| 色 | ○ | 1つ以上 |
| 在庫数 | ○ | サイズ × 色の表で入力する |

- サイズ × 色の組み合わせ1つを「バリエーション」と呼ぶ。在庫はバリエーションごとに持つ。
- 商品一覧は、商品名で検索でき、カテゴリーで絞り込める。在庫が0以下の商品は目立つように表示する。
- 商品やバリエーションを削除しても、データは実際には消さない(論理削除)。過去の売上が参照しているため。削除したものは会計画面に出さない。
- サイズや色を減らしたときも、そのバリエーションは論理削除する。

**カテゴリー**
- オーナーが自由に追加・名前の変更・並べ替えできる。
- 商品が登録されているカテゴリーは削除できない。

### F2 会計

**流れ**
1. カテゴリーで絞り込み、商品をタップする。
2. サイズと色を選ぶ。バリエーションが1つしかない商品は、選ぶ画面を出さずにそのまま追加する。
3. カートで数量を増やしたり減らしたりする。0にするとカートから消える。合計(税込)、税抜、うち消費税、点数を表示する。
4. 「お預かり金額を入力」を押すと電卓画面が開く。
5. 預かった金額を入力すると、お釣りを大きく表示する。足りない場合は赤で「不足」と金額を表示し、確定できない。
6. 「会計を確定」を押すと保存する。お釣りを大きく表示した完了画面を出す。「次のお客様へ」で会計画面に戻る。

**電卓画面**
- 0〜9、00、1文字削除、クリアのキーを置く。
- 「ちょうど」(合計と同じ金額を入れる)、「＋1,000」「＋5,000」「＋10,000」(押すたびに足す)のボタンを置く。
- 金額は打ち間違いに気づけるよう大きく表示する。目安はお預かりとお釣りが 44〜72px、キーは高さ 64px 以上。
- 入力できるのは7桁(9,999,999円)まで。
- PC ではキーボードでも操作できる。数字キーで入力、Backspace で1文字消す、Enter で確定、Esc で戻る。

**在庫**
- 確定するとバリエーションの在庫を減らす。
- 在庫を超えて会計しようとしたときは警告を出すが、会計はできる。在庫数はマイナスになってもよく、商品管理で赤く表示して登録漏れに気づけるようにする。

**会計番号**
- 形式は `YYYYMMDD-NNN`。営業日ごとに001から振る。例:`20261023-007`

### F3 会計履歴・返品

- 日付を前後に切り替えられる。「今日」ボタンで今日に戻る。
- その日の会計件数、現金売上、返金額を表示する。
- 会計の一覧は時刻の新しい順に並べる。1件選ぶと明細が出る。明細には商品、色・サイズ、数量、金額、合計、税抜、消費税、お預かり、お釣り、返金の記録を表示する。

**返品**
- 明細の商品ごとにチェックを入れて返品する。数量が2以上の明細は、返品する数を選べる(返品できるのは、まだ返品していない数まで)。
- 画面の中で返金額を確認してから「返品を確定」を押す。ブラウザの確認ダイアログは使わない。
- 確定すると返金を記録し、在庫を戻す。元の会計は変更せず、明細に「返品済み」と表示する。
- 返金は返品した日の営業日に記録する。過去の日の会計を今日返品した場合も、今日の返金になる。

### F4 レジ締め

- 1営業日につき1件記録する。保存し直すと上書きする。
- 入力するもの
  - 開店時の釣り銭準備金(前日の値を最初から入れておく)
  - 閉店時に数えた枚数:1万円札、5千円札、2千円札、千円札、500円玉、100円玉、50円玉、10円玉、5円玉、1円玉。＋−ボタンでも、数字の入力でも入れられる
  - メモ(過不足の理由など)
- 自動で計算するもの
  - レジにあるはずの現金 = 準備金 + その日の現金売上 − その日の返金
  - 数えた現金 = 金種ごとに「額面 × 枚数」を足したもの
  - 過不足 = 数えた現金 − レジにあるはずの現金
- 過不足は、0なら緑で「過不足なし」、プラスなら黄で「過剰」、マイナスなら赤で「不足」と表示する。
- 保存した時点の売上と返金の値も記録しておく。後で会計が変わっても、締めた時点の数字が残るようにするため。

### F5 帳簿

- 日別表示(月を選ぶ)と月別表示(年を選ぶ)を切り替えられる。
- 集計の数字:会計件数、売上(税込)、税抜、消費税、返金、差引売上(売上 − 返金)
- 日別表示では、一覧に定休日など会計がない日も表示する。
- カテゴリー別には、点数、売上(税込)、構成比を表示する。
- 「Excel をダウンロード」で、表示している期間の .xlsx を保存する(§7)。

### F6 ログイン

- Supabase Auth のメールアドレスとパスワードでログインする。
- 新規登録の画面は作らない。オーナーのアカウントは Supabase の管理画面で作る。
- ログイン状態は端末に残し、毎回ログインしなくていいようにする。

## 6. 金額と税の計算ルール

- 金額はすべて円単位の整数で扱う。小数は使わない。
- 消費税は、1回の会計(1枚の取引)ごとに税込合計からまとめて計算し、1円未満は切り捨てる。インボイス制度の端数処理のルールに合わせる。
  - 消費税額 = floor(税込合計 × 10 ÷ 110)
  - 税抜金額 = 税込合計 − 消費税額
  - 例:税込合計 11,270円 → 消費税 1,024円、税抜 10,246円
- 返金も、1回の返品ごとに同じ式で消費税額を出す。
- 明細ごとの消費税額は持たない。カテゴリー別の集計は税込金額で出す。
- お釣り = お預かり − 税込合計。マイナスになる会計は保存できない。
- 計算は `src/lib/money.ts` にまとめ、単体テストを書く。データベース側(§8 の関数)でも同じ式で計算して保存する。

## 7. Excel 出力

- ファイル名:日別表示なら `帳簿_2026-10.xlsx`、月別表示なら `帳簿_2026.xlsx`
- 金額の列は数値として出力し、表示形式は `#,##0` にする。Excel でそのまま足し算などに使えるようにするため。

| シート | 1行の内容 | 列 |
|---|---|---|
| 集計 | 1日(または1か月) | 日付、件数、売上(税込)、税抜、消費税、返金、差引売上。最後の行に合計 |
| 会計一覧 | 1会計 | 会計番号、日付、時刻、点数、合計(税込)、税抜、消費税、お預かり、お釣り |
| 売上明細 | 1明細 | 会計番号、日付、時刻、商品名、カテゴリー、色、サイズ、数量、単価(税込)、金額(税込)、返品数 |
| 返品 | 1返品 | 返品日、時刻、元の会計番号、商品名、色、サイズ、数量、返金額(税込)、税抜、消費税 |
| カテゴリー別 | 1カテゴリー | カテゴリー、点数、売上(税込)、構成比 |
| レジ締め | 1営業日 | 日付、準備金、現金売上、返金、レジにあるはずの現金、数えた現金、過不足、メモ |

## 8. データモデル

PostgreSQL(Supabase)を使う。ID は `uuid`、日時は `timestamptz` で持つ。

```
categories
  id, name, sort_order, created_at

products
  id, name, category_id → categories, price_incl int, cost int,
  is_active bool, created_at, updated_at

product_variants
  id, product_id → products, size, color, stock int(マイナス可),
  size_order int, color_order int, is_active bool
  unique(product_id, size, color)

sales                      … 1会計
  id, sale_no text unique(YYYYMMDD-NNN), business_date date, sold_at timestamptz,
  total_incl int, tax_amount int, total_excl int, received int, change int,
  created_at

sale_items                 … 会計の明細
  id, sale_id → sales, variant_id → product_variants,
  product_name, category_name, size, color,   ← 会計時点の値を保存しておく
  unit_price_incl int, qty int, line_total int, returned_qty int default 0

refunds                    … 1回の返品
  id, sale_id → sales, business_date date, refunded_at timestamptz,
  amount_incl int, tax_amount int, amount_excl int, memo

refund_items
  id, refund_id → refunds, sale_item_id → sale_items, qty int, amount_incl int

register_closings          … レジ締め
  id, business_date date unique, opening_float int,
  cash_sales int, refunds_total int, expected int,   ← 締めた時点の値
  counts jsonb(例:{"10000":3,"5000":1,…}), counted_total int, difference int,
  memo, closed_at timestamptz

settings
  key, value(税率、前日の準備金など)
```

- 商品名、カテゴリー名、価格は会計の時点で `sale_items` に書き写す。後で商品を編集しても、過去の帳簿が変わらないようにするため。
- 集計は、`sales` を `business_date` で、`refunds` を自分の `business_date` で集計する。

## 9. 処理の一貫性と安全性

- 会計の確定と返品の確定は、データベース関数(RPC)の中で1つのトランザクションとして処理する。途中で失敗したら全部取り消す。
  - `create_sale(items, received)`:合計と税を計算し、会計番号を振り、`sales` と `sale_items` を作り、在庫を減らす。お預かりが合計より少なければエラーにする。
  - `create_refund(sale_id, items)`:返品できる数を超えていないか確かめ、`refunds` と `refund_items` を作り、`returned_qty` と在庫を更新する。
- 合計金額はブラウザから送られた値を使わず、データベース関数の中でバリエーションの現在の価格から計算し直す。
- 確定ボタンは押したらすぐ無効にし、二重に送られないようにする。関数には冪等キーとしてブラウザで作った uuid を渡し、同じキーの会計を2回作らない。
- 全テーブルに RLS(行レベルセキュリティ)を有効にし、ログインしたユーザーだけが読み書きできるようにする。
- 新規登録は Supabase の設定で無効にする。
- Supabase の service role キーはブラウザ側のコードに入れない。

## 10. 非機能要件

| 項目 | 内容 |
|---|---|
| 操作性 | ボタンは高さ 44px 以上、主な操作のボタンは 64px 以上。マウスのホバーがないと使えない操作は作らない。ダブルタップでの拡大を防ぐ(`touch-action: manipulation`) |
| 画面サイズ | iPad の横向き(1024px 以上)を基準にする。縦向きと PC でも崩れないこと |
| 表示 | ライト表示とダーク表示の両方に対応する |
| 速さ | 会計を確定してから完了画面が出るまで、1秒以内を目安にする |
| エラー | 通信に失敗したときは、何が起きたかと、もう一度押せばいいことを画面に表示する。カートの中身は消さない |
| バックアップ | GitHub Actions で週1回 `pg_dump` を取り、GitHub Actions の Artifacts に保存する(保存期間は90日)。あわせて、月に1回 Excel を保存しておく運用をすすめる |
| ブラウザ | iPad の Safari(最新版と1つ前)、Chrome と Edge(最新版) |

## 12. 開発の進め方

GitHub の Issue とプルリクエストで進める。`main` は常に本番にデプロイできる状態にしておく。

| フェーズ | 内容 | 完了の条件 |
|---|---|---|
| 0 | 開発環境の準備:Vite + TS、ESLint、Vitest、CI、Supabase(開発用・本番用)、Cloudflare Pages | プルリクエストで CI が通り、プレビュー URL が出る |
| 1 | ログイン、カテゴリーと商品の管理、テーブル定義とマイグレーション | 商品を登録・編集でき、在庫が保存される |
| 2 | 会計(カート、電卓、`create_sale`)、`money.ts` とそのテスト | 会計すると売上が保存され、在庫が減る |
| 3 | 会計履歴と返品(`create_refund`) | 一部の商品を返品でき、在庫と返金が正しく記録される |
| 4 | レジ締め | 過不足が計算されて保存される |
| 5 | 帳簿と Excel 出力 | 出力した .xlsx を Excel で開くと、集計が画面と一致する |
| 6 | PWA、iPad の実機での確認、バックアップ、本番データの準備 | 店で実際に1日使える |
